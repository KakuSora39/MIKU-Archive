# MIKU Archive 源代码

这是当前初音未来 Live / BD 收藏管理器的完整项目源码，可自行修改、重新编译。桌面版采用 Swift + AppKit + WKWebView；收藏界面采用原生 HTML、CSS、JavaScript，没有 React、Electron 或第三方运行时。Python 仅负责构建。初始数据保存在 JSON 中。

## 文件结构

```text
miku-live-archive/dist/
  index.html       页面结构、中文文案、筛选控件与编辑表单容器
  style.css        配色、字体、布局与窄屏适配
  app.js           收藏数据、筛选、编辑、统计、导入与导出逻辑
  seed.json        首次启动的 51 条目录数据及官方来源
miku-live-desktop/
  Main.swift       原生窗口、菜单、WebKit、文件对话框及网页通信
  Icon.swift       应用图标绘制
  build.py         构建离线 .app、生成图标并进行本机签名
```

网页源码已重新排版，方便阅读；功能与已交付版本一致。源码包不含账户凭据、Sites Git 元数据或个人收藏备份。

## 修改入口

- 修改界面文字：`index.html`；部分动态文案位于 `app.js` 的 `render()`。
- 修改颜色、字号与布局：`style.css`，主色在 `:root`。
- 修改收藏筛选与进度算法：`app.js` 的 `eligible()`、`render()`。
- 修改编辑字段：`app.js` 的 `fields` 数组；新增字段时同步考虑初始数据及导入校验。
- 修改初始目录：`seed.json`。`id` 必须唯一且稳定；导入合并依赖它。
- 修改菜单、原生导入导出、外部链接行为：`Main.swift`。
- 修改图标：`Icon.swift`。

## 编译桌面应用

当前构建目标是 Apple Silicon（M 系列）Mac，macOS 13 或更高版本。
需要 Python 3 和 Apple Command Line Tools；无需安装 Node.js 或 Python 第三方库。

首次缺少编译工具时，在终端运行：

```sh
xcode-select --install
```

进入本 README 所在的项目文件夹后运行：

```sh
python3 miku-live-desktop/build.py
open "build/MIKU Archive.app"
```

产物为 `build/MIKU Archive.app`。脚本从网页源码生成离线资源、编译 Swift、生成图标并验证本机签名。签名为本机临时签名，未做 Apple Developer 分发签名或公证。

如要支持 Intel Mac，请将构建脚本的目标架构改为 `x86_64-apple-macos13.0`，并在相应环境验证。当前源码未提供 Windows 或手机应用构建。

- 收藏保存在 WebKit / 浏览器的 `localStorage`，键为 `miku-archive-v1`。
- 桌面应用与网站的数据独立保存，没有云端同步或后台自动抓取。
- `seed.json` 只用于首次初始化。修改它不会覆盖用户已有收藏。
- 更新或替换应用前，请在应用中导出 JSON；有疑问时可通过备份重新导入。
- 保持应用标识 `local.sora.mikuarchive`、存储键与安装路径稳定，避免存储位置变化。
- 应用内“已收集”和“已下载”独立；进度分母目前只统计“确认有 BD 且发行状态含已发行”的条目。
- 如需让新的目录条目进入已有收藏，可以在界面手动新增，或准备 schema 1 的备份并导入。相同 id 会以备份记录替换，因此先导出当前备份。

- **撤销**：修改图鉴观看 / 想看标记及备注、影像缺失标记、保存或删除影像记录、删除自建 Live 后，底部提供 12 秒的“撤销”。仅保留最近一次可撤销操作；超时或关闭提示后不再提供该次撤销。删除自建 Live 时，其观看标记和备注一起移除，撤销时一并恢复。已确认的备份导入会清除旧撤销入口。
- **备份状态**：设置中显示上次导出时间，并比较当前图鉴 / 影像内容与那次导出的内容。数据改动后提示重新备份；撤销回相同内容可恢复“一致”状态。主题、字号和浏览设置不计入未备份修改。桌面版只在文件写入成功后登记；取消 / 写入失败不更新时间。网页版记录“已发起下载”，实际文件保存以浏览器为准。
- **导入预览**：网页版与桌面版使用同一个预览面板，显示影像数量、同编号替换数量、观看标记 / 备注、内置资料修订及自建演出数量。取消预览不改数据；全部校验通过后才写入，写入出错尝试恢复原存储内容，仍兼容 schema 1 旧备份。
- **字号**：设置 → 外观 → 界面字号，提供标准 / 较大，覆盖卡片、资料、表格、筛选控件和设置文字；即时生效并记住选择。
- **更新记录**：关于页按版本展开，当前提供 1.5.0 和 1.4.0 的真实更新记录。app-info.json 的 version / releasedAt / changes 描述当前版本，history 保存旧版，页面自动合并显示，避免重复维护当前版本。

`archive-actions.js` 维护短时撤销、内容校验值、备份预览及合并。`miku-backup-meta-v1` 仅保存导出时间、渠道和内容校验值，不保存额外的备份副本；导入的设置与备份状态不覆盖当前设备。完整备份新增 appVersion 说明，schema 仍为 1。

原生回归新增撤销与过期、删除后备注恢复、备份一致 / 修改检测、导出内容快照、导入预览 / 取消 / 确认 / 错误回滚、字号切换和版本历史。`--self-test --test-restart` 还会验证重载后的字号和备份时间。


## 1.6.0：五档字号、封面和歌单扩展约定

设置 → 外观中的字号滑块有五个刻度：紧凑、标准、舒适、较大、特大。拖动或使用方向键即时预览，偏好仍保存在 `miku-settings-v1`，`textSize` 改为整数 1–5；旧 `standard` / `large` 自动对应 2 / 4。重启继续使用已选档位。

打开任意演出 → 编辑演出资料 → 卡片封面，可上传 2 MB 内的 JPG、PNG 或 WebP，或填写图片直链。图片从卡片右上角向左渐隐，过渡区叠加模糊图层，保留左侧系列、年份、类型。未设置封面或图片加载失败时继续显示文字卡面。封面来源 / 署名可单独记录，并在详情展示。本版没有批量填入未经核实的海报。

本机上传的图片会等比例缩放并转为 JPEG 卡片缩略图（最长边不超过 480 像素，单张 data URL 不超过 12 KiB），以 data URL 保存于该演出的 `atlasEdits[id].coverUrl`，离线可用并随完整 JSON 备份携带；直链只备份链接，需要联网加载。署名字段为 `coverCredit`。图片读取 / 解码失败不会替换原封面；取消编辑不落盘。移除封面后保存即可恢复文字卡面。大量图片可能占用较多本机存储，保存失败仍保留旧数据。

`live-assets.js` 提供封面检查 / 渲染和歌单预留约定，按现有稳定演出 ID 关联。歌单页面、导入器、播放器均尚未实现。后续功能可沿用以下结构，不用另造演出 ID：

```json
{
  "atlasEdits": {
    "primary-26": {
      "setlist": {
        "schema": 1,
        "sourceUrl": "https://example.com/setlist",
        "notes": "场次说明",
        "songs": [
          {"title": "曲名", "artist": "作者 / 演唱者", "songId": "", "section": "本篇 / Encore", "notes": ""}
        ]
      }
    }
  }
}
```

歌曲按数组顺序排列，可重复曲名；`songId` 暂为可选外部标识。`setlist: null` / 缺省表示尚未录入，`songs: []` 表示已建立空歌单。预留只读接口 `window.MikuArchive.live.getSetlist(eventId)` 返回深拷贝或 null，`setlistSchema` 为 1。`normalizeSetlist()` 校验协议和内容；完整备份仍为 schema 1，能保存 / 恢复这些扩展数据。普通资料编辑以及导入不含新字段的旧备份不会清除封面和歌单字段；显式空封面或 null 歌单可清除对应内容。

验证：原有目录 / 版本检查；原生 `--self-test` 覆盖五档及旧设置迁移、封面显示 / 移除、表单保留扩展字段、备份往返和非法数据拒绝；`--self-test --test-cover-upload` 覆盖真实 FileReader / 图片解码、上传保存、损坏和超限图片、替换链接、取消编辑；`--self-test --test-restart` 覆盖最大字号及浏览位置重载恢复。测试均使用独立临时数据。


## 1.7.0：官方主视觉与通用初音封面

当前 263 条演出中，207 条匹配特定官方主视觉 / 活动形象，56 条尚未确认，使用官方通用初音形象；27 条项目资料中 23 条匹配、4 条通用。84 张去重缩略图位于 `dist/covers/`，随桌面应用与网页源代码一起提供，离线可用，不写入 localStorage。通用图来自 piapro.net 官方角色页，署名 Art by KEI。这里的“通用”并不表示图片进入公共领域；来源、作者和权利信息均保留。

完整清单见 `封面核对清单.md`，包括每条演出的封面、官方出处、原始图片地址和未确认原因。对应映射维护于 `scripts/references/event-covers.json`，由 `catalog_covers.py` 接入目录构建，避免手改生成文件后被覆盖。官网页面来源优先；失效 / 证书异常 / 城市版本未匹配的条目不猜图。SNOW MIKU LIVE 使用当年度 SNOW MIKU 官方活动主视觉，详情明确说明，后续新条目尚无映射时自动使用通用初音。

魔法未来 2020 大阪与东京分别绑定不同主视觉。2023 札幌的 10th Anniversary 仍使用 2022 主题，交响乐 2018–2019 大阪场也沿用所属年度主题，不按演出年份错误换图。交响乐城市图尚未确认时使用通用初音，不把其他城市版套入。部分群像缩略图通过 `focus: [x, y, width, height]`（0–1，相对于去除透明边缘后的图片）突出初音；原图始终可从详情来源核对。

封面优先级：自选本机图片 / 链接 → 当前演出已匹配官方图片 → 官方通用初音。编辑中的“恢复默认封面”清除自选覆盖；新增自建条目默认使用通用初音。详情显示官方来源、署名与替代说明。图片加载失败时也回退到通用图。旧备份、自选封面、演出资料及歌单预留接口继续兼容。完整备份不重复携带内置图片，只保存原有自选图片 / 地址；内置图片由应用版本提供。

普通编译不联网。调整并核对 manifest 中的图片来源后，macOS 上可运行 `python3 scripts/sync_covers.py` 重新下载和生成缩略图（使用 `PrepareCovers.swift`），更新校验值，再运行 `python3 scripts/test_covers.py` 和原有目录检查。重新生成的图仍需人工核对，工具不自动认定图片匹配。图片最大边 640 像素，生成时保留绘制内容，仅去除透明留白或按明确焦点裁切。


## 1.8.0 封面构图

在演出详情的「卡片封面 → 编辑封面」拖动预览右侧，或用横向、纵向和缩放滑块调整。内置封面可直接调整，也可以获取官方图片直链或上传本机图片。保存后，下载的图片以缩略图保存在本机并进入备份，原始直链保留为来源。再次编辑时直接读取本机副本，构图通过独立的 `coverFrame` 字段保存。网页版直链下载需要图片服务器允许跨域读取。

内置缩略图等比缩放并保留完整原图背景。卡片右侧使用固定比例的清晰区域，周围由原图的模糊层填充。默认构图可在 `event-covers.json` 中配置，个人调整保存在演出修订里。旧版保存过的直链封面可通过「获取并编辑图片」转换为本机副本。


## 1.9.0 网页截图和可视化取景

演出详情 → 卡片封面 → 编辑封面 → 打开官网并截图。macOS App 会打开单独的网页窗口，可浏览、滚动和修改地址。找到图片后点击「框选截图」，拖出所需范围，再点「使用选区」。取景框调好后点「应用构图」，最后点「保存演出资料」。

本机上传、图片直链和网页截图都会进入同一个取景编辑器。卡片右侧的清晰区域加宽，并与编辑框使用相同比例，背景向左渐隐。保存后，缩略图、构图和来源地址留在本机，并进入 JSON 备份。独立网页截图窗口仅在 macOS App 中提供，网页版可使用系统截图并上传。


## 1.10.0 演出卡片和主视觉渲染

每场演出保留自己的卡片，以 16:9 主视觉开头。主视觉底部约 24% 纵向渐变至同主题的卡片表面。下方按系列、正式名称、日期、地点、场馆和个人标记排列。标题最多两行，整张卡片可用鼠标或键盘打开详情。

默认按透明像素和宽高比选用透明立绘、横版铺满或氛围融合。内置资源的透明度由 `ProfileCovers.swift` 在维护时计算。自选图片在首次需要时检测并缓存。氛围模式在接近视口时才挂载模糊层，默认模糊 32px、饱和度 0.75、亮度 0.88、背景扩展 1.18 倍，前景维持原始比例。透明立绘使用系列配色，待核实条目显示系列及年份占位。

演出详情 → 卡片封面 → 编辑封面 → 调整显示范围。可选模式、横版裁切焦点、缩放及偏移，现有官网截图、直链和本机上传仍可使用。渲染参数保存在可选 `artworkConfig` 和原有 `coverFrame` 中，并进入 JSON 备份。内置原图无需重裁或替换。对部分旧跨域图片直链，浏览器只能读取尺寸，可通过手动选择模式或重新下载解决。

### 主视觉编辑与素材（1.11.0）

- 在图鉴打开一场 Live，选择「编辑演出资料 → 主视觉」。可以打开官网截图、获取图片直链、上传 JPG／PNG／WebP（每张最大 16 MB），或将已有素材关联到该场演出。列表显示分辨率、宽高比、来源及正在使用的图片。解除关联会保留原图供其他场次复用。
- 「编辑主视觉」同时预览封面和完整 Live 卡片。可以选 Landscape、Poster Stage、Ambient、Cutout、Archive 或自动模式，拖动封面调整位置，也可在「裁剪原图」中拖出自由选区或选择预设比例。点击「应用构图」后仍需「保存演出资料」。
- Archive 使用演出已有的资料生成带「原创档案封面」标记的封面，支持 Minimal、Archive、Electronic。可复用已导入的 Logo，使用前须填写官方来源并确认已核实。
- 「设置 → 主视觉与素材」可调整尚未单独配置的演出所使用的默认值，并清理可重建的缩略图。单场「恢复默认构图」保留已选择的图片，再次使用当前全局默认值。「恢复默认封面」同时切回内置来源。
- 新素材按原始字节的 SHA-256 去重。IndexedDB 分开保存素材信息、原始文件和可清理的缩略图。《演出资料》的 `artworkMediaIds` 保存关联列表，`artworkAssetId` 保存当前图片，`artworkConfig` 保存模板、背景、标准化裁剪与 Archive 样式，`coverFrame` 保留位置和缩放。旧记录的 `coverUrl`、`coverSourceUrl` 与构图字段继续读取。旧版若只保存了缩略图，能保留的仍是该缩略图。
- 官网框选截图的原图是选区得到的截图文件。导入新素材后，原图已进入素材库，取消单场编辑只撤销演出关联和构图。自选素材来源可在单场表单中填写，也可用「保存为素材来源」供其他场次复用。
- 完整 JSON 备份可携带本机图片原图及引用。导入预览会列出原图数量。全局设置保存在当前设备。内置素材随应用提供，使用缩略图资源，可通过官方直链重新获取更高分辨率的图片。
